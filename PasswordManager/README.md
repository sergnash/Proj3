# Password Manager CLI

Локальное хранилище паролей на Python: SQLite3 для записей, Fernet
(`cryptography`) для шифрования паролей, scrypt для вывода ключа из
мастер-пароля.

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Для Linux/macOS активация виртуального окружения:

```bash
source .venv/bin/activate
```

## Запуск

```text
python password_manager.py
```

Мастер-пароль запрашивается один раз, после чего открывается меню:

```text
==============================================
 Менеджер паролей
==============================================
 1. Добавить запись
 2. Показать пароль по названию
 3. Список записей
 4. Изменить запись
 5. Удалить запись
 6. Сгенерировать пароль
 0. Выход
```

Пункт выбирается вводом номера. После выполнения пункта показывается
результат (или сообщение об ошибке), пароль — если он был получен или
сгенерирован — копируется в буфер обмена, а возврат в меню выполняется
нажатием Enter. Мастер-пароль повторно вводить не нужно; выход — пункт
`0` (или `Ctrl+C`, `Ctrl+D`).

При первом запуске программа попросит создать мастер-пароль (не короче
8 символов) и подтвердить его. Из мастер-пароля через scrypt выводится
ключ шифрования ключа (KEK), которым заворачивается ключ хранилища Fernet;
результат сохраняется в `.key`. При следующих запусках нужен этот же
мастер-пароль: без него `.key` не развернуть; на ввод даётся три попытки.

### Настройка генерации пароля

Перед каждой генерацией (пункт `6`, пункт «Добавить запись», `--generate`
в «Изменить запись») программа предлагает длину и отдельно спрашивает про
каждый тип символов:

```text
Параметры генерации:
Длина пароля (8-64, Enter — 16): 
Типы символов (Enter — да):
  Прописные (A-Z)? [Y/n]: 
  Строчные (a-z)? [Y/n]: 
  Цифры (0-9)? [Y/n]: 
  Специальные (!@#$%^&*_)? [Y/n]: 
```

- Длина — от 8 до 64 символов, по умолчанию 16.
- Каждый тип включается отдельно: `y`/`д` — да, `n`/`н` — нет, Enter — да.
  Например, `y`, `n`, `y`, `n` даст пароль только из прописных букв и цифр.
- Нужно оставить хотя бы один тип: если ответить `n` на все, вопросы
  повторятся.
- В пароле гарантированно есть хотя бы один символ каждого выбранного типа;
  пароль перемешивается криптографическим генератором `secrets`.

### Копирование в буфер обмена

Показанный пароль автоматически копируется в системный буфер обмена,
о чём выводится сообщение «Пароль скопирован в буфер обмена.». Это
работает для сгенерированных паролей и для показа сохранённого пароля.

Копирование выполняется так: пакет `pyperclip`, если он установлен,
иначе системная утилита — `clip` (Windows), `pbcopy` (macOS),
`wl-copy`/`xclip`/`xsel` (Linux). Если ни один способ недоступен,
выводится предупреждение, а пароль остаётся на экране.

### Разовые команды

Для скриптов и быстрых операций сохранён и режим одной команды:

```text
python password_manager.py <команда>
```

В этом режиме мастер-пароль придётся вводить при каждом запуске.

| Команда | Действие |
|---|---|
| `add` | Интерактивно добавить запись: название, логин, пароль. Программа спрашивает, сгенерировать пароль или ввести вручную (введённый пароль виден на экране). |
| `get [НАЗВАНИЕ]` | Показать логин и расшифрованный пароль. Название можно передать аргументом или ввести после запроса. |
| `list` | Показать названия и логины всех записей. |
| `delete [НАЗВАНИЕ]` | Удалить запись по названию (с подтверждением). |
| `update [НАЗВАНИЕ]` | Изменить название, логин или пароль. Пустое поле оставляет значение прежним; `-g`/`--generate` создаёт новый пароль с выбором параметров. |
| `new` | Сгенерировать пароль с выбором длины и типов символов; `-l`/`--length N` задаёт длину сразу. |

Примеры:

```powershell
python password_manager.py
python password_manager.py add
python password_manager.py get Google
python password_manager.py list
python password_manager.py delete Google --yes
python password_manager.py update Google --generate
python password_manager.py new --length 24
```

Мастер-пароль вводится скрыто, а пароль записи при ручном вводе
отображается на экране как обычный текст. После ручного ввода
программа показывает пароль и просит подтверждение; если в нём есть
фрагмент, похожий на путь к файлу (например, `C:\...`), выводится
предупреждение — так случайная вставка из буфера не попадёт в базу.
Для `delete` можно использовать `-y`/`--yes`, чтобы пропустить
подтверждение. В `update` пустой ввод оставляет поле
без изменений, а `-g`/`--generate` заменяет пароль сгенерированным.
Если у `new` не указать `--length`, длина и типы символов запрашиваются
интерактивно.

## Где хранятся данные

- `passwords.db` — база SQLite с таблицами `settings` и `entries`.
- `.key` — JSON с ключом Fernet, завёрнутым в KEK из мастер-пароля, солью
  и параметрами scrypt. Без мастер-пароля бесполезен; без самого файла
  сохранённые пароли не восстановить.

Оба файла создаются в каталоге скрипта. Каталог можно переопределить
переменной окружения `PASSWORD_MANAGER_DATA_DIR`:

```powershell
$env:PASSWORD_MANAGER_DATA_DIR = "C:\Users\User\AppData\Local\PasswordManager"
python password_manager.py
```

Схема создаётся автоматически при старте (`CREATE TABLE IF NOT EXISTS`), а при
обновлении программы доводится миграцией: в базе версии 1 не было колонки
`updated_at`, она добавляется при первом запуске (`PRAGMA user_version`).
Записи хранятся в виде: название, логин, зашифрованный пароль, дата создания и
дата последнего изменения. Названия сравниваются без учёта регистра.

## Тесты

```powershell
python -m unittest -v test_password_manager.py
```

Тесты работают с временным каталогом и не затрагивают реальное хранилище.
Интерактивное меню проверяется подстановкой ответов вместо `input()` и
`getpass()`, буфер обмена при этом подменяется заглушкой.

## Безопасность

- Пароли шифруются Fernet; в базе хранится только токен.
- При удалении записи SQLite затирает освобождённые страницы
  (`PRAGMA secure_delete = ON`), после чего файл базы сжимается (`VACUUM`),
  поэтому токен удалённого пароля не остаётся в файле.
- Ключ Fernet завёрнут в KEK, выведенный из мастер-пароля через scrypt
  (n = 32768, r = 8, p = 1, соль 16 байт; параметры лежат в `.key`). Сам
  мастер-пароль нигде не хранится и не хешируется — он проверяется только
  тем, что разворачивает ключ.
- Мастер-пароль вводится один раз за сеанс, поэтому он реже попадает в
  историю терминала или в буфер обмена, чем при запуске команды на каждое
  действие.
- Скопированный пароль остаётся в системном буфере обмена и доступен
  другим программам до перезаписи — очищайте буфер после использования.
- При ручном вводе пароль записи отображается на экране, поэтому
  не вводите его при посторонних.
- Без мастер-пароля `.key` бесполезен, без `.key` бесполезна база.
  Сделайте резервную копию `.key` — при его потере пароли не восстановить.
- Хранилища старого формата (открытый `.key` + SHA-256-хеш в `settings`)
  переводятся в новый автоматически при первом вводе мастер-пароля.
- Ограничения: логины и названия хранятся открытым текстом; права `0600`
  защищают файлы только на POSIX — на Windows права наследуются от папки,
  поэтому держите каталог данных в защищённом месте. Смена мастер-пароля
  пока не реализована.
- Для реального продукта стоит добавить Argon2id, системное хранилище
  ключей и перезаворачивание ключа при смене мастер-пароля.
